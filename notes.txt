enumerated means that something has a defined set of values it can hold.
For example, we will alwasy have sunday - saturday. 
static and final, mean that those values cant be changed, but data types
can change during the course of a program and enumerated data types allow for that
to happen. Additionally, an enum is a refernce type which means it behaves 
more like a class or an interface. This means you can create methods and
variables inside the enum declaration. 

ENUM DECLARATION EXAMPLE

public enum DayOfWWeek{
	SUNDAY,
	MONDAY,
	TUESDAY,
	WEDNESDAY,
	THURSDAY,
	FRIDAY,
	SATURDAY;
}

we can also assign numeric values to those days, for example

public enum DayOfWeek{
	SUNDAY(0),
	MONDAY(1),
	TUEDAY(2),
	WEDNESDAY(3),
	THURSDAY(4),
	FRIDAY(5),
	SATURDAY(6);

	private int value;
	private DayOfWeek(int value){ // constructor
		this.value = value;
	}
}

Now an enum is actually super sick becaause the point of it is making accessing
variables easier. Like if someone started typing in the name of the enum
DayOfWeek. the predefined values will show up.

objects vs primitives
Alright so, basically you have a primitive int, and an object Integer.
Each of the primitives has their corresponding wrapper. In Java, a wrapper class
is an object-oriented class that encapsulates a primitive data type (like int,
double, or boolean) into an object.  This mechanism allows primitive values to be
treated as objects, enabling their use in collections (such as ArrayList or 
HashMap), generics, and APIs that require object references rather than 
raw data types.

to convert an Integer into an int you can do this

public class Main{
	public static void main(String[] args) {
		Integer myInt = new Integer(5000);
		System.out.println("Integer value = " + myInt);
		// convert it now
		int newInt = myInt;
		System.out.println("int value = " = newInt);
	}
	}

the output of the above will be:
	Integer value = 5000
	int value = 5000

Java also has Run-time Magic which can convert it, as shown above by itself 
at run time when you have an Integer object put into an int argument. Memory of
int vs Integer is 4 bytes vs 16-24 bytes. 

Interfaces are like a class, but it only has fields and methods. It kind of
lets you implement multiple inheritance, but not fully. here is an example

package multiexample;
interface Scan {
	public String scanDoc(String doc);
}

interface Copy{
	public String copyDoc(String doc);
}

public class MultiExample implements Scan, Copy {
	@Override
	public String scanDoc(String doc){
		System.out.println("Scanning the Document = " + doc);
		return doc;
		}
	@Override
	public String copyDoc(String doc) {
		System.out.println("Copying the Document = " + doc);
		return doc;
	}

	public static void main(String[] args){
		MultiExample multi = new MultiExample();
		multi.scanDoc("Rates.doc");
		multi.copyDoc("Rates.doc");
	}
}

the @Override command is added to make sure youre calling/creating the desired
method. Healthy habit to have as well. 

Throwing and catching exceptions is very important. The difference between the two
is that one solves the issue immediately, and the other makes it someone else's 
problem. An example of this is will be shown with a password maker

BAD EXAMPLE:
public void setPassword(String password) {
    // No 'if' check. No 'throw'. Just straight to business.
    this.password = password.toUpperCase();
}

// OTHER DEVELOPER WORKING AND CALLING YOUR METHOD
public class Main {
    public static void main(String[] args) {
        User user = new User();

        // Dave doesn't know he HAS to check for null.
        // He just got this password from a user form that was left blank.
        String userInput = null;

        user.setPassword(userInput); // Dave calls your method.

        System.out.println("User created successfully!");
    }
}

// GOOD EXAMPLE
public void setPassword(String password) {
    if (password == null) {
        throw new IllegalArgumentException("Password cannot be null, Dave!");
    }
    if (password.isEmpty()) {
        throw new IllegalArgumentException("Password cannot be empty!");
    }
    this.password = password.toUpperCase(); // Safe! We KNOW password is good.
}

public class Main {
    public static void main(String[] args) {
        User user = new User();
        String userInput = null;

        try {
            user.setPassword(userInput); // Dave calls your method.
            System.out.println("User created successfully!");
        } catch (IllegalArgumentException e) {
            // DAVE catches the EXACT error YOU threw.
            System.out.println("Error: " + e.getMessage());
            // Prints: "Error: Password cannot be null, Dave!"
            // The program DOES NOT crash. It just prints a nice message.
        }
    }
}

so a simpler way to look at it, is by just reading the words. When encountering
an exception, you can throw it to be caught by another method.
